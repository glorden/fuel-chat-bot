# VK-бот «где заправиться»

Бот для тематической VK-беседы про заправку топливом: молча читает сообщения беседы, вытаскивает из них структурированные факты по АЗС (что есть в наличии, длина очереди, технические перерывы/слив бензовоза, когда сообщили) и отвечает на вопросы участников этими фактами, явно показывая свежесть данных.

Архитектура — в [ARCHITECTURE.md](ARCHITECTURE.md), статус разработки — в [PROGRESS.md](PROGRESS.md).

## Как это работает

- Бот подключён к сообществу VK как участник беседы с полным доступом к переписке.
- Читает **все** сообщения, но отвечает по правилам из `AUTO_REPLY_ON_QUESTION` (см. ниже) — либо по явному упоминанию бота.
- По умолчанию классификация/извлечение/резолв станции — на правилах/regex, ответы — на шаблонах (без LLM). Опционально можно включить разбор через LLM флагом `LLM_ENABLED`, провайдер — `LLM_PROVIDER` (`mistral` по умолчанию, либо `groq`/`gemini`) — устойчивее к опечаткам, нестандартным формулировкам и репортам без явного номера марки; при сбое/лимите бот прозрачно откатывается на правила. Текст ответа в любом случае собирается из шаблонов, не LLM — это защита от галлюцинаций.

## Команды в чате

- `!вкл` / `!выкл` — включить/выключить автоответ на вопросы без упоминания бота. Только для `ADMIN_ID`.
- `!лимит` / `!лимиты` — список известных лимитов отпуска топлива по брендам. Доступна всем.

## Команды в личке

Владелец (`ADMIN_ID`) может управлять ботом в личных сообщениях сообществу, не засоряя беседу: те же `!вкл` / `!выкл` плюс `!помощь` со списком команд. Личка — только канал управления: факты оттуда не пишутся и не читаются, сообщения от всех остальных игнорируются без ответа.

- `!модерация` — переключить режим, в котором ответ не уходит в беседу сразу, а приходит сюда карточкой на подтверждение.
- `+7` / `-7` — отправить или отклонить черновик №7; голые `+` / `-` — то же для последнего. Не подтверждённый за 15 минут черновик не отправляется вовсе.
- `!помощь` — справка со списком команд и текущим состоянием бота.

## Установка

```bash
git clone https://github.com/glorden/fuel-chat-bot.git
cd fuel-chat-bot
python -m venv .venv
.venv\Scripts\activate      # Windows
pip install -r requirements.txt
copy .env.example .env      # затем заполнить значения
```

## Настройка VK

1. В настройках сообщества: **Сообщения → настройки бота** → включить возможности бота → разрешить добавление сообщества в беседы.
2. Сгенерировать токен доступа сообщества с правом «Сообщения» (управление сообществом → работа с API).
3. Добавить сообщество в целевую беседу как обычного участника, затем выдать ему права администратора беседы **или** «полный доступ к переписке» — без этого бот видит только сообщения с явным упоминанием себя.
4. Заполнить `.env`: `VK_TOKEN`, `GROUP_ID`, `ALLOWED_PEER_IDS`, `ADMIN_ID`.

`ALLOWED_PEER_IDS` обязательна: бот обслуживает только перечисленные в ней беседы, из
остальных не читает и в них не отвечает, даже если сообщество туда добавили. Без неё бот
не стартует.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `VK_TOKEN` | токен доступа сообщества с правом «Сообщения» |
| `GROUP_ID` | числовой ID сообщества |
| `ALLOWED_PEER_IDS` | `peer_id` обслуживаемых бесед через запятую; обязательна, без неё бот не стартует |
| `ADMIN_ID` | VK ID пользователя, которому доступны команды `!вкл`/`!выкл` — в чате и в личке (см. «Команды в чате», «Команды в личке») |
| `AUTO_REPLY_ON_QUESTION` | `true`/`false` — отвечать ли на вопросы без явного упоминания бота |
| `MODERATION_ON_REPLY` | `true`/`false` — ждать ли подтверждения владельца перед отправкой ответа (по умолчанию `false`); живое состояние — в БД, переключается `!модерация` |
| `MODERATION_TTL_MINUTES` | сколько минут черновик ждёт подтверждения, потом не отправляется (по умолчанию `15`) |
| `FRESH_MINUTES` | отчёт свежий, если ему не больше стольки минут (по умолчанию `240`) |
| `STALE_MINUTES` | отчёт «устарел, но ещё показываем», если не больше стольки минут; дальше — «старые данные» (по умолчанию `480`) |
| `MIN_REPLY_GAP_SECONDS` | минимальный интервал между ответами бота одному и тому же автору, страховка от флуда (по умолчанию `5`) |
| `RAW_TEXT_TTL_DAYS` | через сколько суток обнуляется сырой текст сообщения; сам факт остаётся навсегда (по умолчанию `30`) |
| `PROCESSED_MESSAGE_TTL_DAYS` | через сколько суток удаляются записи дедупа (по умолчанию `7`) |
| `AUTHOR_HASH_SECRET` | ключ для отпечатка автора вместо VK-идентификатора; пусто — берётся `VK_TOKEN` |
| `LLM_ENABLED` | `true`/`false` — использовать ли LLM для классификации/извлечения/резолва станции (по умолчанию `false`) |
| `LLM_PROVIDER` | `mistral` (по умолчанию), `groq` или `gemini` — какой провайдер использовать, если `LLM_ENABLED=true` |
| `GROQ_API_KEY` | бесплатный ключ с [console.groq.com](https://console.groq.com) (нужен, только если `LLM_PROVIDER=groq`) |
| `LLM_MODEL` | модель Groq, по умолчанию `llama-3.3-70b-versatile` |
| `GEMINI_API_KEY` | бесплатный ключ с [aistudio.google.com](https://aistudio.google.com) (нужен, только если `LLM_PROVIDER=gemini`) |
| `GEMINI_MODEL` | модель Gemini, по умолчанию `gemini-flash-lite-latest` |
| `MISTRAL_API_KEY` | ключ с [admin.mistral.ai](https://admin.mistral.ai) (нужен, только если `LLM_PROVIDER=mistral`) |
| `MISTRAL_MODEL` | модель Mistral, по умолчанию `ministral-8b-2512` — датированная, не алиас `-latest` (см. ARCHITECTURE.md) |
| `LLM_TIMEOUT_SECONDS` | таймаут запроса к LLM в секундах, по умолчанию `10` |
